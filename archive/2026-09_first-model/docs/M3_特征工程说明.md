# M3 · SMILES → RDKit 描述符/Morgan fingerprint → feature matrix

## 一、产出

- `feature_matrix.parquet` / `feature_matrix_sample.csv`：**1934 行 × 2624 列**，一行=一条配方/实验记录，与 M2 的 `merged_formulations.csv` 行数完全对应
- `featurize_m3.py`：特征工程脚本，从 `merged_formulations.csv` 单一输入即可完整重跑，可审计
- `status_summary.csv`：四个脂质角色（ionizable/helper/sterol/peg）各自的解析状态统计
- `failed_smiles_log.csv`：全量解析校验时发现的、源数据里本身就损坏的 SMILES 清单（2条）

## 二、列结构

一行的列大致分六块：

- 标识列：`source_dataset` / `source_row_id` / `formulation_id`
- 状态列：`ionizable_lipid_status` / `helper_lipid_status` / `sterol_lipid_status` / `peg_lipid_status`（见下方"五种状态"）
- 配比列：四个角色的 `*_pct`（延续 M2）
- 分子特征列：五个角色（ionizable/helper/sterol/peg/payload）各自 7 个 RDKit 描述符（MolWt/LogP/TPSA/HBD/HBA/可旋转键数/环数）+ 512 位 Morgan fingerprint（radius=2），共 5×(7+512)=2595 列
- `payload_type_*`：核酸大类的 one-hot（mRNA/siRNA/DNA/ASO/protein/gold_nanoparticles/empty/mRNA,siRNA/small_molecule_drug）
- 目标列（留给 M4 用，不是特征）：`particle_size_nm` / `pdi` / `zeta_potential_mv` / `encapsulation_efficiency_pct` / `formation_ok`，以及溯源用的 `paper_doi` / `process_notes` / M2 遗留的两个审计标记列

同一角色如果由多个组分组成（比如 PMC_IVR 某配方 helper 是 "DPPC+MSPC"），描述符取均值、指纹做按位 OR 合并——代表"这个角色里包含哪些结构特征"，不是精确的加和。

## 三、五种状态，别混为一谈

每个角色每一行会落在以下五种状态之一：

- **not_applicable**：这个体系本来就没有这个角色（比如经典脂质体没有电离脂质、Luciani 没有测 payload）
- **unresolved**：有名字，没查到结构（比如 LNP Atlas 里 37% 的"Custom lipid"占位符，无法追溯）
- **unparseable**：有名字也有 SMILES 字符串，但 RDKit 解析不出来——这是**源数据本身**的问题，不是我们的问题（详见下方"全量校验的发现"）
- **approximated**：用近似/理想化结构代替，主要是 PEG 化脂质（详见下方"PEG 近似结构怎么造的"）
- **resolved**：真实核实过的精确结构

## 五、PEG 近似结构怎么造的（这是唯一"编造"了结构的地方，讲清楚假设）

PEG 化脂质天生没有单一精确结构——PEG 链长本身是一个分布，商品名"PEG2000"指的是平均分子量。近似方法：**重复单元数 n = round(标称分子量 / 44)**（44 g/mol 是一个 -OCH2CH2- 重复单元的分子量），甲氧基封端，按常见的连接化学建模：

- **mPEG-DSPE**：氨基甲酸酯键连接在 DSPE 的游离氨基上（PEG2000→n=45，PEG5000→n=114，PEG10000→n=227）
- **DMG-PEG5k**：碳酸酯键连接在 DMG（二肉豆蔻酰甘油）的游离羟基上（n=114）
- **C14-PEG2000**：醚键直接连接十四烷基和 PEG（n=45）

这些结构**不代表真实产品的精确结构**，只是让 MolWt/LogP/TPSA/指纹能反映"这是个多大的 PEG 化分子"这个量级信号，比完全空着强，但不能当成精确值使用。`peg_lipid_status='approximated'` 这个标记就是为了让你（或 M4 建模时）能随时把这批行单独摘出来做敏感性分析，或者干脆排除。

还有一个例外没有近似：PMC_IVR 的 `mPEG2000-DSPE-LMWP`（还带了一段寡肽 LMWP），因为多肽部分会显著改变分子量和结构，用纯 PEG-DSPE 近似会比留空更误导人，所以继续留在 unresolved。LNP_Atlas 里还有 96 行是裸的"PEG1000/2000/3000/5000"（不知道连的是哪个脂质骨架），也没有猜测骨架，同样留空——这是刻意判断，不是漏做。

## 六、全量校验的发现（这一步不是走过场）

之前只做过 5 分子冒烟测试，这次按原计划把全表 356 个不重复 SMILES 片段全部跑了一遍解析校验，抓出 2 条**源数据自己就是坏的**：

1. `LNPAtlas_948`（ionizable_lipid_name="Custom lipid"）：SMILES 语法错误（unclosed ring），和 cKK-E12 那 5 行共享同一个坏字符串，但因为名字本身不明确，没有替换。
2. `LNPAtlas_821`（peg_lipid_name="DSPE-2armPEG2000"，一种双臂/支链 PEG 脂质）：SMILES 语法错误（价键数超限）。这个是真实存在的商品化合物，但结构比线性 PEG 复杂，没有贸然手造，留在 unparseable。

这两条都不是我们处理流程引入的错误，是 LNP Atlas 原始数据集本身的数据质量问题，全部记录在 `failed_smiles_log.csv` 里，没有静默丢弃对应的行——这两行的其它列（粒径、PDI等）依然保留在最终表里，只是这两个角色的分子特征是空的。

## 七、一个中途发现并修复的真实 bug

早期版本里，PMC_IVR 多组分角色（比如"HSPC+HePc"）的 SMILES 是用 `'+'` 连接多个子结构的，全量校验时才发现这是个 bug——真实 SMILES 里的 `+` 是电荷符号（比如磷脂头基的 `[N+](C)(C)C`），会把好端端的单个分子字符串从中间切断，之前抽查的 5 个分子刚好都没有带电原子所以没暴露出来。已经改用专用分隔符 `' |&| '` 重新生成，`merge_schema.py` 和这份脚本都同步改了。这也是坚持"先抽查、再全量、全量时留错误清单"这个流程本身的价值所在——如果没做这一步，会有一批磷脂类脂质的指纹是错的但没人发现。

## 八、已知局限（延续 M2 的坦诚风格）

1. Morgan fingerprint 用的是 512 位、radius=2，M4 建模如果发现表现不够好，可以调大位数重算，这里选 512 只是为了先出一版能用的基线。
2. 描述符/指纹目前偏"配方形成难易度"相关（MolWt/LogP/TPSA 这类通用理化性质），不包含任何和透皮/毛囊渗透直接相关的特征——跟之前讨论过的 Track A/Track B 领域错配是同一件事，这份特征矩阵服务于 Track A（全身给药）。
3. payload 那一块：LNP_Atlas 是核酸大类（mRNA/siRNA等），做了 one-hot；PMC_IVR 是具体小分子药物，用的是 payload_smiles 算出来的真实分子描述符/指纹，**没有**额外把药物名字也做 one-hot——这是刻意的，如果连药物名字都编码进去，等于让模型能直接"背答案"而不是从结构学习，这样做没有意义。
4. LNP_Atlas 电离脂质里 850 行 not_applicable 看着多，实际上是因为 LNP Atlas 各行经常只填了部分角色（很多行本身没有完整四组分记录），不代表数据有问题。
