# M2 · 三源合并总结

## 一、产出

- `merged_formulations.csv` / `.parquet`：合并后的统一表，**1934 行 × 26 列**（LNP Atlas 1092 + Luciani 570 + PMC_IVR 272，行数完全对得上，没有丢数据）
- `merge_schema.py`：合并脚本，可重跑、可审计

> ⚠️ 更正（相对上一版）：早前这里写"PMC_IVR 271 行、完全没有脂质组成数据"，是错的——当时只连上了 zip 里 144MB 的一部分，没拿到完整的 `liposome_IVR.db` 数据库。拿到完整库后重新查，配方组成表（`formulation_composition`，385行）是真实存在的，论文摘要里说的"lipid composition features"没有说错。这版已经把 PMC_IVR 的脂质组成并进来了，行数也从 271 变成 272（见下方"已知局限"里的说明）。

## 二、统一 schema 设计

一行 = 一条配方/实验记录，核心列：

- `source_dataset` / `source_row_id` / `formulation_id`：来源标记，任何时候都能追溯回原始数据
- `ionizable_lipid_*` / `helper_lipid_*` / `sterol_lipid_*` / `peg_lipid_*`（各带 `_name`/`_smiles`/`_pct`）：四个脂质角色统一命名
- `particle_size_nm` / `pdi` / `zeta_potential_mv` / `encapsulation_efficiency_pct`：物理性质，跨三源统一单位和格式
- `payload_type` / `payload_smiles`：装了什么（核酸类型 或 药物名+结构）
- `formation_ok`：配方是否成功成型（只有 Luciani 提供了这个判据）
- `process_notes`：工艺条件，保留成可读文本（各源格式不同，暂不强行拆分）
- `release_curve_file`：指向体外释放曲线文件（只有 PMC_IVR 有）
- `ratio_order_was_ambiguous`：见下方"重要发现"

三源各自的角色映射：LNP Atlas 四组分对齐最直接；Luciani 只有三组分，把"主磷脂"映射到 helper_lipid 角色（因为它起的是结构支撑作用，不是电离脂质），ionizable 留空；PMC_IVR 也没有电离脂质（跟 Luciani 一样是经典脂质体），但**有 helper/sterol/peg 三类组分的真实数据**，来自数据库里的 `formulation_composition` 表，按组分名字关键词分类（含"PEG"→peg，含"Cholesterol"→sterol，其余→helper）。

PMC_IVR 的脂质 SMILES：数据库本身没存（只存了药物 API 的结构式），已额外手动核实并入（详见 `PMC_IVR_lipid_component_smiles.csv` 和 `M2_PMC_IVR_data_dictionary.md`）——31 个组分里 16 个是结构单一、已在 PubChem 核实的标准脂质，直接给了 SMILES；5 个天然混合物（HSPC/Soy PC/EPC/asolectin/Egg SM）、3 个 PEG 化脂质（链长有分布）、5 个定制合成脂质（结构未二次核实）都刻意留空，没有编造。并入后 helper_lipid_smiles 覆盖 98/272（36.0%），sterol_lipid_smiles 覆盖 180/272（66.2%，因为这类只有 Cholesterol 一种，全部覆盖了 name），peg_lipid_smiles 覆盖 0/272。

## 三、⚠️ 重要发现（合并过程中抽查出来的，不是小问题）

LNP Atlas 论文正文写的摩尔比顺序是"电离脂质:PEG脂质:固醇:辅助脂质"，我们上次 M1 就是照这个顺序解析的。这次做合并前按惯例抽查了几个业内公认的经典配方核对（比如 DLin-MC3-DMA 的标准配方是 50:10:38.5:1.5，PEG占比很小；BioNTech/Pfizer 疫苗用的 ALC-0315 标准配方是 46.3:9.4:42.7:1.6），发现**同一个脂质在数据集里，不同行的第2位和第4位数字会互相调换**——比如 ALC-0315 有的行写成 `46.3:1.5:42.7:9.5`，有的行写成 `46.3:9.4:42.7:1.6`，这两个数字对调了。也就是说论文声称的"统一顺序"在实际数据里并没有被严格贯彻，可能是不同来源论文各自的原始报告顺序不同，标准化流程没有完全统一。

**这次的处理办法**：电离脂质（第1位）和固醇（第3位）经核对是可靠的，唯独 PEG 和辅助脂质（第2、4位）不可信直接按位置分配。改用了一个基于化学常识的规则——**取值较小的那个记为 PEG 占比，较大的记为辅助脂质占比**（真实 LNP 配方里 PEG 脂质几乎永远是占比最小的成分，这是行业内非常稳定的规律）。用这个规则重新核对了 MC3、ALC-0315 等已知配方，全部对上了。

统计下来，**1092 行里有 966 行（88.5%）原始数据的第2/4位顺序其实是"反着"的**——如果没有做这次抽查、直接按论文说的顺序信了，这批数据里绝大多数的 PEG/辅助脂质占比会是错的。`ratio_order_was_ambiguous` 这一列标记了每一行是否经过这次修正，方便你以后审计或者不放心的话自己再查。

这也是当初定 M1/M2 流程时反复强调"拿不准就去核实、别凭文档/经验直接信"这条原则，这次是用在了"用已知的真实配方去反向验证数据顺序"上——效果很直接。

## 四、已知局限（老实说清楚，不藏着）

1. **PMC_IVR 脂质组成覆盖不完整**：272 行里 helper_lipid 100% 有值，sterol_lipid 66.2%（180行），peg_lipid 46.3%（126行）——不是每个配方都用了全部三类组分，这是真实情况不是缺失。**SMILES 部分覆盖**：已人工核实 31 个组分中 16 个标准脂质的结构并入表中（helper_lipid_smiles 36.0%、sterol_lipid_smiles 66.2%），但 5 个天然混合物、3 个 PEG 化脂质（链长可变）、5 个未二次核实的定制合成脂质仍留空——M3 做 RDKit 特征化时这批脂质暂时无法算描述符，尤其是 PEG 脂质（peg_lipid_smiles 目前 0% 覆盖），需要额外决定用"平均链长近似结构"还是别的处理方式。
2. Luciani 里 25% 的行（`formation_ok=0`）是形成失败的配方，训练模型前记得按这个字段过滤，别把失败样本当正常数据点用。
3. `ratio_order_was_ambiguous` 这个修正是基于"PEG占比通常最小"的经验规则，不是 100% 确定——极少数刻意设计高 PEG 占比的实验配方可能被分配错，如果后续做严谨分析，这批标记为 True 的行建议留一个"低置信度"标签。
4. `process_notes` 目前是没拆开的文本（各源格式不统一），M3/M4 如果要用到具体工艺参数（比如流速、pH），还需要针对这个字段再写解析逻辑。
5. LNP Atlas 里约 5% 的行（55/1092）摩尔比字符串本身就不是标准 4 段格式，这批行的脂质占比全部留空，没有强行凑数。
6. PMC_IVR 行数从旧版的 271 变成 272：旧版是照 `backend_data.csv`（271行）数的，这次改成直接照数据库 `IVR` 表（272行）走，多出来的 1 行具体差异没有细查，量级很小，不影响整体结论。
7. **`formulation_composition` 摩尔比总和不等于100的问题，已查清楚并修复**：141个配方里136个原始总和落在98-102之间（正常mol%口径+四舍五入），5个明显偏离（>2）：
   - **formulation_ID=3**（DSPC:Chol:PEG = 2.00:1.00:0.14，总和3.14）和 **formulation_ID=7**（HSPC:Chol = 1.5:1，总和2.50）——去查了原始论文原文，**不是数据错误，是原文本身就按"摩尔比"而非"mol%"报的**：1_2.pdf方法部分原文写"with mole ratio 2:1:0.14"；1_3.pdf的表格里同一张表其余配方是"57/38/5"这种百分比格式，唯独这一行（LMVVD）写的是"1.5/1"——同一篇论文内部报告口径都不统一，是原始文献的问题。
   - **formulation_ID=109/111/113**（三篇同批AmBisome相关论文）总和都是105.00，比100多5%，量级较小但仍纳入了修复范围。
   - **已实际归一化，不再只是文档标注**：`merge_schema.py` 现在会把这5个配方的 helper/sterol/peg_pct 按行总和重新换算成真正的 mol%（比如配方3：63.69/31.85/4.46，加总=100），并新增 `composition_pct_was_renormalized` 列标记哪些行被改过，方便审计。归一化后全部272行（除下面的41/49两行本身缺失外）的三列加总都精确等于100。
   - **formulation_ID=41、49**（两篇AmBisome相关论文）molar_ratio全部是NaN，纯粹是原始数据缺失，跟百分比格式无关，不参与归一化（除以NaN总和还是NaN）。**这里额外发现并修复了脚本自己的一个bug**：pandas对全NaN的分组求和会静默返回0.0而不是NaN，导致这两个配方在合并表里曾经被误标成"helper/sterol_pct=0%"（看起来像是"确定不含该成分"，实际是"根本没数据"）。已用 `min_count=1` 修复，现在正确显示为缺失值。
