# 特征工程说明（小分子子集）

日期：2026-10-19
对应协议：`docs/evaluation-protocol.md` 第七节（特征定义与泄漏控制）。本文件只负责实现，不改协议定下的边界。

## 〇、一条命令跑通

```bash
python3 scripts/build_features.py --config configs/smallmol_baseline.yaml
python3 scripts/leakage_check.py  --config configs/smallmol_baseline.yaml
```

第一条从 `merged_formulations_v2.csv` 和 SMILES 出发，产出分析单元表和特征矩阵；第二条做泄漏检查。两条都是幂等的，重跑结果一致。

换成大分子子集只需要把 `configs/smallmol_baseline.yaml` 里的 `subset.name` 改成 `large_molecule`，代码一行不用动。

### 代码结构

| 文件 | 职责 |
|---|---|
| `lnp/subset.py` | 子集定义（small_molecule / large_molecule / all）、payload 分组键（InChIKey） |
| `lnp/features.py` | 描述符、指纹、制剂组成、脂质结构、工艺特征的计算 |
| `lnp/dataset.py` | 按协议 1.1 节的去重键把原始行折叠成分析单元，定义 T1/T2/T3 的目标 |
| `scripts/build_features.py` | 串起来的入口，带禁止字段断言 |
| `scripts/leakage_check.py` | 五项泄漏检查 |
| `configs/smallmol_baseline.yaml` | 全部可调项（子集、指纹位数、低频类别阈值、禁止字段清单、种子） |

### 环境版本（写进 `data/processed/feature_manifest.json`，每次重跑都记录）

Python 3.13.16 / pandas 3.0.5 / numpy 2.5.3 / **RDKit 2026.09.1** / scikit-learn 1.9.1

## 二、特征分块与每个特征的物理含义

### M-desc：payload 分子描述符（12 个）

| 特征 | RDKit 函数 | 物理含义 |
|---|---|---|
| `payload_mol_wt` | `Descriptors.MolWt` | 分子量，Da。分子大小的最基本量 |
| `payload_logp` | `MolLogP` | 辛醇/水分配系数的计算值，亲脂性。决定药物是进脂质双层还是留在水相内核 |
| `payload_tpsa` | `TPSA` | 拓扑极性表面积，Å²。极性大小，与膜通透性负相关 |
| `payload_hbd` | `NumHDonors` | 氢键供体数。与脂质头部基团的相互作用能力 |
| `payload_hba` | `NumHAcceptors` | 氢键受体数。同上 |
| `payload_rot_bonds` | `NumRotatableBonds` | 可旋转键数，分子柔性。柔性分子更容易嵌进双层 |
| `payload_ring_count` | `RingCount` | 环数。刚性骨架的量度 |
| `payload_aromatic_rings` | `NumAromaticRings` | 芳环数。π 堆积能力，与插入双层的取向有关 |
| `payload_fraction_csp3` | `FractionCSP3` | sp³ 碳占比，三维饱和程度。平面芳香分子与立体饱和分子的区分 |
| `payload_heavy_atoms` | `HeavyAtomCount` | 重原子数，与分子量相关但不受同位素和氢影响 |
| `payload_mol_mr` | `MolMR` | 摩尔折射率，分子极化率的量度，与范德华相互作用强度相关 |
| `payload_balaban_j` | `BalabanJ` | 分子图的拓扑连接性指数，描述支化程度 |

选这 12 个的理由：全部是「载药分子的物理化学性质」这一层的量，和「药物怎么被装进脂质体」有机制上的联系，而不是随手取一堆描述符。没有用 RDKit 的全部 200 多个描述符——73 个样本配 200 多个描述符必然过拟合，而且大量描述符之间高度相关，加进去只增加噪声。

### M-fp：payload Morgan 指纹

`rdFingerprintGenerator.GetMorganGenerator(radius=2, fpSize=2048)`，即 ECFP4 等价物。表示分子里有哪些局部结构环境。

2048 位配 73 个样本显然是过参数化的。协议第七节写明：**位的筛选只能在交叉验证的训练折内做**，特征矩阵里存全量 2048 位，筛选留到第四步建模时在折内完成。这样做的代价是建模代码要自己管这件事，好处是不会出现「用全体数据筛特征」这种泄漏。

### F-comp：制剂组成（10 列，只有 T1 用）

| 特征 | 含义 |
|---|---|
| `helper_lipid_pct` / `sterol_lipid_pct` / `peg_lipid_pct` | 三类脂质的摩尔百分比 |
| `has_helper_lipid` / `has_sterol_lipid` / `has_peg_lipid` | 该配方是否含这类组分 |
| `*_pct_is_missing` | 该组分存在但占比数据缺失（本子集只有 4 行） |
| `n_lipid_classes` | 用了几类脂质（1 到 3） |

T2 和 T3 的目标就是组成，所以这一块在 T2/T3 的特征里**不存在**（config 的 `tasks.t2.blocks` / `tasks.t3.blocks` 里没有 `f_comp`）。

### F-lipid：脂质结构特征（1055 列，只有 T1 用）

- helper 和 sterol 两个角色各 12 个 RDKit 描述符（同 M-desc 的 12 个）+ 各 512 位 Morgan 指纹
- 多组分脂质（如 `DPPC+MSPC`，本子集 141 行属于这类）：描述符取算术均值，指纹按位 OR。这表示「这个角色里包含哪些结构特征」，不是精确的加和。沿用 M3 的做法，口径一致
- 7 个派生标记：

| 特征 | 含义与选它的理由 |
|---|---|
| `n_helper_components` / `n_sterol_components` / `n_peg_components` | 该角色由几个组分构成。单一脂质和混合脂质是不同的物理体系，这是化学含义明确的量 |
| `helper_is_natural_mixture` 等 | 是不是天然来源混合物（HSPC / Soy PC / EPC / asolectin / Egg SM）。这类没有单一结构式，缺结构是真实情况不是数据缺失 |
| `peg_mw_da` | PEG 链分子量（2000 / 5000 / 10000），从脂质名字解析。PEG 脂质在原始表里 SMILES 覆盖率为 0%，链长是唯一可用且确有物理含义的信息 |

**为什么不用脂质名字的 one-hot**：本子集 30 个 helper 名字里很多只出现一两次，等于论文身份的代理变量（协议 7.2 节禁止）。用结构描述符 + 上面这几个化学含义明确的标记代替。

**为什么 PEG 不造近似结构**：M3 曾为 PEG 脂质造过「平均链长近似结构」。本轮不这么做，因为本子集只有 4 个 PEG 脂质名字，差别主要就是链长，而链长可以直接解析成一个数值特征。编一个假的 SMILES 再从它算 12 个描述符，得到的是 12 个由同一个假设推导出来的相关列，信息量不比一个 `peg_mw_da` 多，还让人以为有结构数据。

**三个近乎常量的列**：`n_sterol_components` 恒为 1（本子集固醇只有 Cholesterol 一种）、`sterol_is_natural_mixture` 恒为 0、`peg_is_natural_mixture` 恒为 0。它们会被第四步折内的方差筛选自动去掉，这里保留是为了跨子集时代码路径一致（大分子子集里固醇不一定只有一种）。

### P：工艺特征（8 列）

| 特征 | 含义 |
|---|---|
| `process_temp_c` | 工艺温度 °C。影响脂质相态（凝胶相/液晶相），直接影响成粒 |
| `process_temp_c_is_missing` | 温度缺失标记（T1 里 21.9% 缺失） |
| `prep_*`（6 列 one-hot） | 制备方法：薄膜水化、薄膜水化+搅拌、薄膜水化+挤出、薄膜水化+超声、微流控、other |

制备方法原始有 16 类而分析单元只有 73 个，**出现次数低于 5 的类别合并成 `other`**（阈值 `features.prep_method_min_count: 5` 写在 config 里，可审计）。不合并的话，只出现一两次的类别等于论文标识。缺失作为 `missing` 单独一类，不丢样本。

微流控相关的三个工艺字段（流速比、总流速、芯片型号）在小分子子集里 100% 缺失（盘点文档 3.6 节），所以不在特征里。**M6 关于「工艺特征是有效信号」的结论建立在微流控数据上，不适用于本轮。**

## 三、缺失值处理

协议 7.3 节写定的，这里是实现结果。

**原则：0 只用在「确实是 0」的地方，其它一律保留 NaN。**

| 情况 | 处理 |
|---|---|
| 某类脂质组分不存在（`*_lipid_name` 和 `*_lipid_pct` 都为空） | 占比填 **0**，`has_* = 0`。这是真值不是填充：核实过，把 NaN 当 0 填回后每行三组分加总精确等于 100.000 |
| 组分存在但占比缺失（`name` 有、`pct` 空，本子集 4 行） | 占比保留 **NaN**，`has_* = 1`，`*_pct_is_missing = 1`，留给折内中位数填充 |
| 脂质没有结构式（天然混合物、未核实的定制脂质） | 描述符和指纹整行 **NaN**（不是 0——指纹全 0 意味着「所有子结构都不存在」，和「没有结构数据」是两件事），另有 `*_is_natural_mixture` 标记区分两种原因 |
| 工艺温度缺失 | 保留 NaN + `process_temp_c_is_missing` 标记 |
| 制备方法缺失 | 归入 `missing` 类别，不丢样本 |

**特征矩阵里不做任何填充。** 填充、标准化、指纹位筛选全部在第四步的交叉验证管线里、只用训练折的数据做（梯度提升树原生支持缺失值，不填充；Ridge 和随机森林用训练折中位数填充 + 缺失指示列）。

各分块的缺失率（T1）：

| 分块 | 缺失占比 |
|---|---|
| M-desc（payload 描述符） | 0% |
| M-fp（payload 指纹） | 0% |
| F-comp（制剂组成） | 0% |
| **F-lipid（脂质结构）** | **39.0%** |
| P（工艺） | 2.7% |

F-lipid 的 39% 是本轮特征侧最大的硬伤：helper 脂质的 SMILES 在小分子子集里只覆盖 36%，而缺的那批主要是天然来源混合物（HSPC、Soy PC、EPC、asolectin、Egg SM），**它们在原始文献里就没有单一结构式，不是我们没查到**。这个缺失无法通过努力消除，只能如实标记。

## 四、泄漏检查（五项，逐个确认）

`scripts/leakage_check.py` 的完整结果在 `docs/leakage_check.json`，逐特征明细在 `docs/leakage_check_detail_t1.csv` 和 `_t3.csv`。

### 1. 禁止字段断言

协议 7.2 节的 19 个禁止字段/子串，对 T1 的 3133 列和 T3 的 2060 列逐列匹配：**0 命中，通过**。这个断言写在 `build_features.py` 里，命中就直接报错退出，不会静默通过。

被挡在外面的高危字段里最重要的是 `structure_type`（SUV / LUV / MLV，是粒径分箱后的标签）和 `process_notes` 原始文本（含 `structure_type`）。

### 2. 单调关系检查

每个非指纹特征与目标的 |Spearman ρ|：**T1 最大 0.505，T3 最大 0.583**。没有任何特征是目标的单调变形（那会接近 1.0）。

### 3. 互信息

T1 互信息最高的非指纹特征是 `payload_hba`（0.651）、`payload_heavy_atoms`（0.632）、`payload_mol_wt`（0.603）。

**但这个排序是误导性的，必须和第 4 项一起看。** 这几个高互信息的特征在单特征分组交叉验证里全部**打不过常数基线**（`payload_hba` 改善 −0.030，`payload_heavy_atoms` −0.012，`payload_ring_count` −0.097，`payload_mol_mr` −0.124，负数表示比直接报均值更差）。原因是 73 个样本上互信息估计本身方差极大，而且这些描述符在化合物内部是常量，互信息捕捉到的是「化合物身份」而不是可泛化的关系。**在这个样本量下，互信息不能用来做特征选择，单特征分组交叉验证才是有效的诊断。** 这条写在这里，是为了防止之后有人拿互信息排序去筛特征。

### 4. 单特征模型（只用一个特征，按化合物分组 5 折交叉验证）

| 特征 | MAE | 常数基线 MAE | 相对改善 | 被 paper 解释的 η² |
|---|---|---|---|---|
| `prep_Thin lipid film hydration and agitation` | 0.176 | 0.248 | **+29.1%** | 0.319 |
| `payload_rot_bonds` | 0.214 | 0.248 | +13.7% | 0.817 |
| `payload_aromatic_rings` | 0.231 | 0.248 | +7.1% | 0.888 |
| `prep_other` | 0.239 | 0.248 | +3.9% | 0.891 |
| `payload_mol_wt` | 0.244 | 0.248 | +1.9% | 0.870 |

61 个非指纹特征里只有 5 个能单独打败常数基线，最强的那个是**制备方法**，不是分子性质。这个结果在建模前就提示了两件事：B2 诊断基线（去掉全部分子特征）会很强，而分子特征的贡献很可能很小。这是预期，不是结论——结论要等第四步按协议跑完。

这里要说清一件事：单特征改善 29.1% 这个数字**不是泄漏**。「薄膜水化+搅拌」这种制备方法不做挤出，粒径自然偏大且分散，这是真实的工艺因果关系，而且制备方法在预测时是已知的输入。它的 η²=0.319 说明它横跨多篇论文，不是单篇论文的标识。

### 5. 代理变量检查

**(a) 对被排除的 `structure_type` 的代理能力**：用单阈值切分看每个特征能不能分辨 SUV/LUV/MLV，相对「永远猜多数类」的准确率增益，**T1 最大 0.154，T3 最大 0.117**。也就是说排除 `structure_type` 之后，没有留下能把它还原回来的特征。这一项是本次检查最关键的一条，因为 `structure_type` 是唯一一个真正高危的泄漏字段。

**(b) 被 `paper_doi` 解释的方差（η²）**：这一项结果不好，必须明说。T1 的 61 个非指纹特征里 η² 中位数 **0.825**，四分之一的特征超过 0.914，**两个特征达到 1.000**：`prep_Thin lipid film hydration` 和 `prep_microfluidics`——这两种制备方法各自只出现在一篇论文里，所以它们在数值上等价于「这条记录来自哪篇论文」的指示变量。

这件事的性质要说准：

- 它**不是**协议 7.2 节意义上的泄漏（没有任何特征包含目标值）
- 它**是**一个真实的混杂通道。按化合物分组交叉验证时，同一篇论文可以同时出现在训练折和测试折（一篇论文里可以有多个化合物），此时一个等价于论文标识的特征就能让模型查到「这篇论文的典型粒径」
- 它的根源是数据结构本身：26 篇论文、73 个配方，每篇论文往往只用一套工艺和一种脂质体系，所以几乎所有特征都和论文高度共线。这不是特征工程能修掉的问题

**处理方式（不改协议，用协议里已经定好的手段）**：

1. 协议第三节已事先规定要跑 **B3 诊断基线（只用 payload 分子特征，去掉制剂和工艺）**。B3 不含任何工艺特征，因此不含这两个 η²=1.0 的列，它给出的是「排除论文代理通道后」的结果。B2（只有制剂+工艺）和 B3 的对比因此有了第二层解读：B2 远好于 B3 不仅说明工艺重要，也可能部分来自论文代理
2. 协议第四节已事先规定要跑 **S3（按论文分组）**。在 S3 下同一篇论文不可能跨训练测试集，论文代理通道被切断。**S1 与 S3 的差距因此是这个混杂程度的直接度量**，第五步报告里会按这个口径解读
3. 本节的 η² 明细（`docs/leakage_check_detail_t1.csv`）随结果一起交付，便于复查

没有为此新增任何特征处理或新的过滤条件——协议冻结后不为结果好看调整做法。

## 五、已知局限（如实列出）

1. **F-lipid 缺失 39%**，且缺失不是随机的：缺的是天然来源混合物，而这类脂质恰好集中在较早的 Doxil 类配方里。模型对这批样本只能依靠 `*_is_natural_mixture` 标记和组成占比，看不到结构
2. **helper 槽位承载多组分混合物**（141 行），描述符取均值、指纹取 OR 都是有损压缩。模型看不到「56.3% 的 helper 里 DPPC 和 MSPC 各占多少」
3. **PEG 脂质无结构数据**，只有链长一个数值特征
4. **2048 位指纹配 73 个样本**是严重过参数化的，折内筛选能缓解但不能消除
5. **几乎所有特征与论文身份高度共线**（η² 中位数 0.825），这是数据结构的属性，不是实现缺陷。S1 与 S3 的差距会量化它
6. 本轮未安装 xgboost（wheel 反复下载中断），梯度提升树用 sklearn 的 `HistGradientBoostingRegressor`，与上一轮口径一致
