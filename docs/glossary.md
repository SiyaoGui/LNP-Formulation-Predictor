# 术语表

这份文件把报告里会出现的建模术语讲清楚，面向没有机器学习背景的读者。看 `modeling/*/README.md` 或 `docs/algorithm-results-en.md` 时可以随时对照。

## 一、四个参照模型（B0 / B1 / B2 / B3）

这四个不是模型，是**四把尺子**。建模最容易骗自己的地方是：算出一个数字，但没有参照物，不知道它到底算好还是算坏。所以在跑任何模型之前先定了四个参照物。

### B0 常数基线（constant baseline）

**完全不看输入，永远报训练集的平均值。**

比如训练集所有配方的粒径平均是 130 nm，那不管给它什么药、什么配方，它都答「130 nm」。这是一个完全不学习的「模型」。

**任何模型如果打不过它，就等于什么都没学到。** 这是最低底线。

### B1 相似性基线（similarity baseline）

**在训练集里找结构最像的那个分子，直接抄它的答案。**

用 Tanimoto 相似度（衡量两个分子结构有多像的标准指标，取值 0 到 1）在 Morgan 指纹上比较。这模拟的是药物化学家不用电脑时会做的事：圣草酚和槲皮素结构接近，那就参考槲皮素的配方。

**模型如果打不过「照抄最像的那个」，那它对专家来说没有增量价值。**

### B2 和 B3：两把诊断用的刀

这两个不是底线，是用来回答「精度差到底差在哪」的工具。

| | 给模型看什么 | 回答什么问题 |
|---|---|---|
| **B2** | 只给配方和工艺，**把分子特征全部删掉** | 如果删掉分子后性能不变，说明分子本来就没起作用 |
| **B3** | 只给分子特征，**把配方和工艺全部删掉** | 如果单靠分子就能预测，说明分子确实携带信息 |

这两把刀是整个项目最值钱的设计。实际结果：

| | 第一轮：预测粒径 | 第二轮：预测包封率 |
|---|---|---|
| B0 常数基线 | 0.253 | 18.40 |
| B2 删掉分子特征 | 0.198（几乎没变） | 15.25（明显变差） |
| B3 只留分子特征 | 0.257（还不如常数基线） | 13.90（明显更好） |
| 完整特征 | 0.192 | 13.41 |

第一轮：删掉分子性能不变，只留分子还不如瞎猜，所以**分子没用**。
第二轮：删掉分子明显变差，只留分子就已经很好，所以**分子是主力**。

没有 B2 和 B3，只会得到「精度差」三个字，不知道该补数据、换特征还是换任务。

## 二、怎么把数据分成训练集和测试集

交叉验证的基本做法：把数据切成 5 份，拿 4 份训练、1 份测试，轮换 5 次。**关键是怎么切。**

### 分组划分（grouped splitting）

同一个分子的所有记录只能全在训练集或全在测试集，不能两边都有。否则模型可以背答案而不是学规律，分数会虚高。

第一轮的编号是 S1 到 S4，第二轮是 G1 到 G3，本质是一回事：

| 第一轮 | 第二轮 | 按什么分 | 防住什么 |
|---|---|---|---|
| S1 | G1 | 按分子 | 模型背答案 |
| S2 | G2 | 按骨架 | 靠「认化学家族」蒙混过关 |
| S3 | G3 | 按论文 | 认出「这是哪个实验室的数据」然后查表 |
| S4 | 无 | 留一分子（每次只留一个分子做测试） | 同 S1，但最大化训练数据 |

**三种分法的结果差异本身就是结论。** 第二轮的例子：

| 分法 | 模型对常数基线的改善 |
|---|---|
| G1 按分子 | +4.99 pp |
| G2 按骨架 | +4.46 pp |
| G3 按论文 | **+0.01 pp** |

前两个站得住、第三个归零，说明模型学到的东西在「换一个新分子」时有效，在「换一个新实验室」时失效。

### Murcko 骨架（scaffold）

把一个分子的侧链全部剥掉，只留环系和连接环的部分。比如阿司匹林剥掉乙酰基和羧基，剩下一个苯环。两个药如果侧链不同但环系相同，骨架就相同，化学上算「同一家族」。

**按骨架分组强制让测试集出现训练时完全没见过的骨架**，这才是真正的泛化考验。

注意：第一轮这个测试**失效**了。15 个化合物恰好对应 15 个不同骨架，一一对应，所以「按骨架分」和「按化合物分」是同一件事。报告里明确禁止把两者差不多解读成泛化良好。第二轮才是真测试：197 个分子只有 28 个骨架。

## 三、随机种子与「5/5」

把数据切成 5 份有很多种切法，具体怎么切取决于一个随机数（种子，seed）。切法不同结果会变。只跑一次然后报告，等于碰运气，而且很容易只报最好看的那次。

所以固定 5 个不同的种子（0 到 4），完整跑 5 遍，每遍单独判断「模型是否显著好于基线」，然后数有几遍成立。

- **5/5**：5 次全部成立，结论稳健
- **0/5**：一次都不成立
- **3/5**：结果不稳定，按本项目标准不算打败

**实例**：第一轮里同一批真值 788 nm 的样品，5 个种子给出的预测分别是 735、920、941、215、328 nm。同一个样本、同一个模型，只换切法，预测差 4 倍。这就是为什么协议明确禁止只报最好的种子。

## 四、不确定度

### Cluster bootstrap（按分子重抽样）

把分子列表随机有放回地抽 2000 次，每次重算一遍指标，取 2.5% 和 97.5% 分位数作为 95% 置信区间。

**关键是按分子抽，不是按行抽。** 同一个分子的多条记录误差是相关的，按行抽会把区间算得过窄，让结论看起来比实际更确定。

### 怎么判断「打败基线」

看的**不是**单个指标的绝对值，而是：

1. 模型与基线的**配对差值**的 95% 置信区间有没有跨过 0
2. 5 个种子的差值符号是否一致

两个条件都满足才算打败。

**实例**：第一轮梯度提升树比常数基线好 0.061（点估计看着不错，相当于好 24%），但区间是 [−0.052, +0.267]，跨过 0，所以**不算打败**。

## 五、指标

| 指标 | 含义 |
|---|---|
| **MAE** | 平均绝对误差，预测值和真值平均差多少 |
| **log10 变换** | 粒径跨 30 到 820 nm，右偏，所以预测 log10(粒径)。MAE=0.19 意思是平均差约 1.6 倍 |
| **pp（百分点）** | percentage point。包封率从 70% 到 75% 是「涨了 5 个百分点」，不是「涨了 7.1%」。为避免歧义统一用百分点 |
| **R²** | 决定系数。0 表示和常数基线一样，负数表示比常数基线还差。本项目只作辅助，因为小样本下它极不稳定 |
| **skill score** | （基线误差 − 模型误差）/ 基线误差。无量纲，用来对比单位不同的几轮 |
| **Aitchison 距离** | 比较两个「加和为 100% 的成分向量」的标准距离，用在预测脂质组成那个任务上 |
| **balanced accuracy** | 各类别召回率的算术平均。用在分类任务上，避免「永远猜多数类」拿高分 |

## 六、算法

三个都用了，每次都全部跑、全部报告。协议规定的顺序是先简单后复杂，有明显提升才往下走。

| 算法 | 一句话 |
|---|---|
| **Ridge 岭回归** | 最简单的线性模型，假设输入和输出是直线关系 |
| **随机森林** | 几百棵决策树投票，能捕捉非线性和交互作用 |
| **梯度提升树** | 树一棵接一棵地建，每棵专门纠正前面的错误。小样本表格数据上通常最强 |

哪个最好不固定：第一轮粒径和第二轮包封率都是梯度提升树最好，大分子那边是 Ridge 最不差（但三个都比常数基线差）。

**没有用深度学习**，这是刻意的。73 到 370 个样本的规模，神经网络几乎必然过拟合，学的是噪声。

**超参数调节**用嵌套交叉验证：在训练折内部再切一次来选参数，绝对不碰测试折。

## 七、目标变量

### EE%（包封率，encapsulation efficiency）

制备时**有多少比例的药物真正被装进了颗粒里**，剩下的留在外面的水相里要被洗掉。

> EE% = 包进颗粒里的药量 / 投料总药量 × 100%

投 10 mg 做制备，颗粒里有 7 mg，外面 3 mg，EE% = 70%。

### 和载药量（drug loading, DL%）不是一回事

| | 分母是什么 | 回答什么问题 |
|---|---|---|
| 包封率 EE% | 投进去的总药量 | 做制备时**浪费了多少药** |
| 载药量 DL% | 颗粒的总重量（药 + 脂质） | 每 100 mg 颗粒里**有多少是药** |

包封率 90% 但载药量只有 1%，意思是药基本没浪费，但要达到有效剂量得用很多脂质。所以数据规格要求两个一起测。

### 为什么从粒径换成包封率

机制上，包封率直接取决于药物分子自身的性质（亲脂性 LogP、电荷状态、氢键能力），而粒径主要由外部工艺决定（挤出膜孔径、超声功率、流速）。这就是第一轮失败、第二轮成功的根本原因。

## 八、判定档位

每一轮的成功标准都在跑模型**之前**写进协议并提交，之后不许改。改了必须单独提交并写明原因和当时已有的结果。

第一轮（`docs/evaluation-protocol.md` 第十节）：成功 / 部分成功 / 不成功
第二轮（`docs/ee-feasibility-protocol.md` 第九节）：可学 / 部分可学 / 不可学

**事先写死很重要**：如果等看到结果再定标准，就可以随便调整到「看起来成功」。协议文件的提交时间早于结果文件夹，可以从 git 历史核实。

## 九、其它常见词

| 词 | 含义 |
|---|---|
| **分析单元（analysis unit）** | 一个唯一配方实验，不是一行记录。原始数据里一行等于一条释放曲线实验，同配方会重复出现多行，按行算会让有效样本量虚高三倍 |
| **数据泄漏（leakage）** | 特征里直接或间接包含了答案。例如 `structure_type`（SUV/LUV/MLV）就是粒径分箱后的标签，用它等于告诉模型答案，已排除 |
| **混杂（confounding）** | 两个因素绑在一起变化，无法分离。本项目最大的混杂是「分子」和「工艺」在文献里几乎总是同时变 |
| **退化（degeneracy）** | 模型表面在跑，实际没学任何东西。本项目记录了两例：一例拟合失败后降级成常数预测；一例 Ridge 不报错但输出恒等于训练集均值 |
| **学习曲线（learning curve）** | 按训练数据量画出的性能变化曲线，用来回答「继续加数据有没有用」 |
| **消融实验（ablation）** | 删掉某一部分特征再跑，看性能变化多少，用来判断那部分特征有没有贡献。B2 和 B3 就是消融 |
