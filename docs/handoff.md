## 一、一句话状态

**现有的 LNP 配方预测模型在严格评估下不成立，但这一轮搞清楚了原因，而且找到了一个可行的方向：目标变量应该从粒径换成包封率，数据应该自己在固定方案下采而不是继续从文献聚合。**

## 三、三条核心结论

### 1. 粒径是工艺的函数，不是分子的函数

三条独立证据：

- 把全部分子特征删掉，误差从 0.192 变成 0.198，几乎没变
- 只留分子特征，误差 0.257，还不如「永远报平均值」的 0.253
- 制备方法单独一个特征就带来 29% 的改善

最直白的证据是数据里的一对实例：atenolol 和 propranolol 来自同一篇论文、同样的脂质组成，只是制备方法不同（超声 vs 搅拌），粒径从 30 nm 变到 800 nm，**差 25 倍**；而这两个药的亲脂性差两个数量级，在同样工艺下粒径完全一样。

**这其实是好消息**：毛囊靶向需要的尺寸区间，调工艺就能稳定做到，不需要模型。我们一直在用 AI 解决一个已经被工艺解决了的问题。

### 2. 换成包封率，四条诊断全部反转

| 诊断 | 第一轮粒径 | 第二轮包封率 |
|---|---|---|
| 最好的模型打败常数基线 | 否（0/5 种子） | **是（5/5 种子，+4.99 pp）** |
| 相似性基线 vs 常数基线 | 更差 | **更好** |
| 只用分子特征 | 打不过常数基线 | **明显更好（5/5）** |
| 删掉分子特征 | 几乎没影响 | **明显变差** |

机制上说得通：包封率直接取决于分子的亲脂性、电荷、氢键能力；粒径不取决于这些。

### 3. 真正的瓶颈是跨实验室不可比，不是样本量

三轮、两个目标变量、样本量从 73 到 370，按论文分组后优势**每次都归零**：

| 轮次 | 按分子分组 | 按论文分组 |
|---|---|---|
| 第一轮粒径 | +0.061 | +0.003 |
| 第二轮包封率 | +4.99 pp | +0.01 pp |
| 第三轮大分子 | 不适用 | 比基线更差 |

第二轮还能看出机制：相似性基线按分子分组时比常数基线好 3.88 pp，按论文分组时反而差 1.79 pp。说明「最相似的脂质」通常就是同一篇论文里的，抄的是那篇论文的测定水平，不是化学规律。物理原因是测定方法、N/P 比、缓冲体系、payload 在论文之间都不一样，同一个分子在两个实验室可以差 20 个百分点。

## 四、我的判断：最重要的启示和下一步

这一节是建议，不是数据结论，看的时候请区分开。

### 最重要的启示

**我们之前问错了问题，而且这不是数据量的问题。** 再多的数据和再好的算法，也学不出一个在物理上不存在于这份数据里的关系。文献数据有个结构性缺陷：几乎每篇论文都是「一种药配一套工艺」，分子效应和工艺效应在数学上不可分离。**补数据的形状比补数据的数量更重要**，这是最有操作价值的一句话。

### 下一步主线

**自己在一套固定方案下采包封率数据。** 完整规格在 `docs/data-spec-ee.md`，核心要求只有一条：固定工艺和配方，只让分子变。

关键参数：

- 40 到 60 个分子，至少 15 个不同骨架，LogP 和电荷类别刻意铺开
- 每个分子至少 3 个**独立制备批次**（不是同一批测三次），用来测批间标准差，那是模型误差的天花板，现在这个数我们不知道
- 必含圣草酚和 2 到 3 个结构相近的黄酮
- 包封率和载药量一起测
- 分三阶段：先用 12 到 16 个分子做方法学摸底，**验收标准是批间标准差小于分子间标准差的一半**，不达标就不要进入主实验

为什么规模比第一轮估计的小（40-60 对 40-100）：单一实验室去掉了跨来源噪声。包封率的学习曲线显示 32 个分子就有 2.70 pp 的效应，63 个到 3.86 之后基本走平。

### 明确不建议做的事

- **不要继续从文献聚合包封率数据。** 第二轮证明跨论文的包封率不可比，混在一起会把真实信号稀释掉
- **不要在现有数据上换更复杂的模型。** 73 到 370 个样本，复杂模型只会过拟合。限制在数据不在算法
- **不要把任何现有数字当成「模型精度」对外引用。** 没有模型打败过相似性基线，而且跨论文时全部失效

## 六、怎么重跑

```bash
# 环境（容器里装过的）
pip install scikit-learn rdkit pyarrow matplotlib tabulate

# 第一轮
python3 scripts/build_features.py --config configs/smallmol_baseline.yaml
python3 scripts/run_modeling.py   --config configs/smallmol_baseline.yaml --out modeling/<新日期>_<说明>
python3 scripts/render_tables.py  --dir   modeling/<新日期>_<说明>
python3 scripts/make_figures.py   --dir   modeling/<新日期>_<说明>

# 第二轮（包封率）
python3 scripts/run_ee_feasibility.py --groups G1 --out modeling/<新日期>_<说明>

# 换大分子子集：只改 configs 里 subset.name 一行，代码不动
python3 scripts/build_features.py --config configs/largemol_baseline.yaml --tasks t1
```

**环境注意事项**（都在报告里记录过）：

- xgboost 在这个容器里装不上（wheel 反复下载中断），梯度提升树用的是 sklearn 的 `HistGradientBoostingRegressor`。三轮用的是同一个实现，所以轮次之间可比。如果之后装上 xgboost，**不要替换已有结果**，另开文件夹跑
- 完整的第一轮 T1 纯拟合时间约 102 分钟，`run_modeling.py` 支持 `--schemes` 分段跑，`metrics.json` 会自动合并，不会覆盖
- 容器重启会丢后台任务，所以脚本改成了每跑完一段就落盘

## 九、两个值得记住的教训

**1. 评估设计是自欺的高发区。** 这个项目早期版本报过 R²=0.43，那是因为同一篇论文的数据同时出现在训练和测试里，等于开卷考试。严格分组后掉到 0 附近。本轮还记录了两例「沉默退化」：模型数字看起来正常，实际上恒等于常数基线，全靠有基线对照才发现。

**2. 消融实验才是把失败变成方向的工具。** 「精度差」三个字没有任何行动指导。「删掉分子特征性能不变，只用分子特征不如报均值」直接告诉我们要换目标变量，我们换了，成功了。B2 和 B3 两条诊断跑起来成本很低，却承载了这个项目最多的信息。
