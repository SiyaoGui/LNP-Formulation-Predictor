## 一、任务定义

### 1.1 分析单元与去重规则（先说这个，因为它决定了后面所有的 n）

**一个分析单元 = 一个唯一配方实验，不是一行记录。**

原始数据里一行等于一条体外释放曲线实验，同一个配方在不同释放介质、不同释放方法下会出现多行，而粒径是配方的固有属性，这些行里是同一个值或接近值（见盘点文档 3.3 节）。直接按行评估会让重复测量的配方在指标里占更大权重，也会让「有效样本量」被高估三倍。

去重键（T1）：`payload_smiles` + `helper_lipid_name` + `helper_lipid_pct` + `sterol_lipid_pct` + `peg_lipid_pct` + `paper_doi` + `prep_method_std`
同一键的多行合并为一个分析单元，目标值取**中位数**（不是均值，避免个别离群测量主导）。

去重键（T2）：`payload_smiles` + `helper_lipid_pct` + `sterol_lipid_pct` + `peg_lipid_pct` + `paper_doi`

**按行评估的版本作为敏感性检验一并报告**，但主结果用去重后的版本。

### 1.2 任务 T1（主目标）：粒径回归

- **输入**：payload 分子特征 + 制剂特征 + 工艺特征（具体分块见第七节）
- **输出**：`log10(particle_size_nm)`，单输出
- **任务类型**：回归
- **过滤条件**（写死，不许再调）：`particle_size_nm` 非空；`particle_size_nm ≤ 1000`（排除 MLV/LMVV 多层囊泡，这是另一类颗粒体系）；`formation_ok != 0`（本子集里该列全空，保留这条只为和大分子子集保持同一套代码路径）
- **为什么取 log10**：粒径右偏，log 变换是这类回归的标准做法，也和前一轮 `train_m4.py` 的口径一致，两轮数字可直接比

**规模（MW ≤ 900）**：158 行 → **73 个唯一配方 / 15 个唯一化合物 / 15 个唯一 Murcko 骨架 / 26 篇论文**，其中 16 个配方的 payload 是荧光探针。目标值 30 到 820 nm，log10 标准差 0.342。

每个化合物的配方数极度不均：30 / 10 / 8 / 8 / 4 / 2 / 2 / 2 / 1 / 1 / 1 / 1 / 1 / 1 / 1。doxorubicin 一个化合物占 30/73（41%），有 7 个化合物只有 1 个配方。

**敏感性检验（不设 MW 上限）**：187 行 → 83 个唯一配方 / 17 个化合物 / 30 篇论文。

### 1.3 任务 T2（可行性探针）：脂质组成预测

- **输入**：只用 payload 分子特征（这是「从分子性质预测配方」这个问题的定义；额外再跑一个加入工艺特征的版本）
- **输出**：`(helper_lipid_pct, sterol_lipid_pct, peg_lipid_pct)` 三组分，加和恒等于 100
- **任务类型**：多输出成分数据回归

**规模（MW ≤ 900）**：88 行 → **27 个唯一配方 / 8 个唯一化合物 / 17 篇论文**，doxorubicin 占 18/27（67%）。

**T2 定位说明**：8 个化合物、27 个配方、22 个不重复的组成向量且大多挤在 helper 55–68 / sterol 29–40 / PEG 3–5 的窄区间。这个规模下 T2 的任何数字都不构成「模型精度」结论。T2 的目的是量化「常数基线（永远预测平均组成）能到什么水平」，用这个数字说明这个任务现在差多少数据，而不是声称建出了模型。**T2 的结果在对外材料里只能用于论证补数据的必要性，不能当作能力证明。** 这条写在协议里，不是事后解释。

### 1.4 任务 T3（2026-10-19 修正新增）：脂质类别组合的分类

**新增理由（在跑任何模型之前发现，见第十二节修改记录）**：盘点阶段把三个组分占比列的 NaN 当成了缺失值，所以 T2 只能用三组分齐全的 88 行。第三步特征工程时核实清楚了：**这些 NaN 不是缺失，是「该配方不含这类组分」**。证据是把 NaN 当 0 填回去之后，270 行（MW ≤ 900 口径下 230 行）里每一行的三组分加总都精确等于 100.000，只有 `IVR_formulation_41` 和 `49` 两行是三列全空的真缺失（M2 文档里记录过这两行曾被 pandas 的全 NaN 求和静默算成 0.0，后来用 `min_count=1` 修掉）。另外 `*_lipid_name` 和 `*_lipid_pct` 两列几乎完全同时存在同时缺失（helper 2 行、sterol 2 行例外），也印证了这一点。

这意味着「这个配方用了哪几类脂质」这个信息在 230 行上都是观测到的，而**这个选择本身就是项目想预测的配方设计决策**（用不用胆固醇、用不用 PEG 化脂质），比三组分的具体百分比更粗但数据多得多。

- **输入**：只用 payload 分子特征（另跑一个加入工艺特征的版本），与 T2 一致
- **输出**：四类之一 —— `helper only`（只有辅助脂质）/ `helper+sterol` / `helper+PEG` / `helper+sterol+PEG`
- **任务类型**：多分类（4 类）

**规模（MW ≤ 900，按 1.1 节 T2 的去重键去重）**：230 行 → **60 个分析单元 / 20 个唯一化合物 / 29 篇论文**。类别分布：全三组分 27、helper+sterol 17、helper only 9、helper+PEG 7，多数类占 45%。

**T3 的定位**：20 个化合物比 T2 的 8 个好，但仍然是小样本，且 doxorubicin 占 25/60（42%）。T3 和 T2 一样属于探针，不是能力证明。它的价值在于用更多数据回答同一个问题：分子性质能不能预测配方设计选择。

#### T2 的成分数据处理方式

三组分加和为常数，是成分数据（compositional data）。**禁止对三个组分各自独立回归再硬归一化**：那样会违反加和约束、产生负值、并且扭曲误差结构。

做法：**ILR（等距对数比）变换**。三组分 → 2 维 ILR 坐标 → 在 ILR 空间建模 → 逆变换回原空间评估。选 ILR 而不是 CLR 的理由：CLR 产生的坐标是奇异的（协方差矩阵不满秩，三个坐标和恒为 0），直接喂给 Ridge 这类带正则的线性模型会有退化问题；ILR 给出满秩的 2 维表示，维度也和自由度一致（3 个组分只有 2 个自由度）。

**代价必须写明**：

1. 27 个样本做 2 维回归，自由度极低
2. PEG 占比普遍只有 3–5%，对数比变换会放大这一维的相对误差——原空间里 PEG 从 5% 预测成 3% 只差 2 个百分点，在 ILR 空间里是很大的偏差。所以**同时报 ILR 空间的距离和原空间每个组分的百分点误差**，两个都看
3. 零值无法取对数。本子集三组分齐全的记录里没有 0 值（最小 PEG 占比 1.67%），所以不需要零值替换；如果之后在大分子子集遇到 0，用乘法替换（multiplicative replacement），替换值记录在当次 config 里

## 二、评价指标

### 2.1 T1

**主指标：跨折合并的 MAE（log10 空间）**，记作 `MAE_log`。

为什么用 MAE 而不是 R² 当主指标，理由是具体的，不是偏好：

1. **R² 在这个样本量下会失效。** 按化合物分组后，15 个化合物里有 7 个只有 1 个配方。LOCO 划分时这些折的测试集只有 1 个点，单点的 R² 在数学上无定义（分母是测试集方差，等于 0）。5 折划分时每折测试集只有 3 个化合物，测试集方差本身波动极大，R² 会跟着剧烈摆动，但这个摆动反映的是测试集成分而不是模型好坏。
2. **R² 依赖测试集方差，跨划分方式不可比。** 本协议要报 4 种划分，用 R² 的话 4 个数字的分母各不相同。
3. MAE 在 log10 空间有直接的物理读法：`MAE_log = 0.1` 等于平均差 1.26 倍，`0.3` 等于差 2 倍。

**但 R² 必须一并报告**，用「跨折合并的 out-of-fold 预测值整体算一个 R²」这一种算法（不是每折算完再平均），因为它是审稿人和评审会问的数字，也是和前一轮 R²=−0.069 对比的唯一口径。R² < 0 意味着不如直接报训练集均值，这个判断本身是有用的。

**辅助指标**：

| 指标 | 说明 |
|---|---|
| `RMSE_log` | 对大误差更敏感，和 MAE 一起看能判断误差是否集中在少数样本 |
| `R²_pooled` | 合并 out-of-fold 预测算一个，口径同上 |
| `median_fold_error` | `10^(median abs error in log10)`，读作「预测值和真值平均差几倍」 |
| `MAE_nm` / `RMSE_nm` | 逆变换回 nm，方便和文献比，但注意 log 空间的均值逆变换不等于原空间均值，只作参考 |
| Spearman ρ | 只看排序关系，对单调变换不敏感，用来判断模型有没有抓到趋势但标定偏了 |

**决策统计量（这个比单个指标更重要）**：模型与每个基线在**同一批 out-of-fold 预测**上的配对 `ΔMAE_log`，以及它的 95% 置信区间（第六节的 cluster bootstrap）。判断「模型有没有用」看的是这个区间有没有跨过 0，不是看 MAE 的绝对值。

### 2.2 T2

**主指标：平均 Aitchison 距离**（预测组成与真实组成在 ILR 空间的欧氏距离，等价于成分数据的自然距离度量）。

**辅助指标**：

| 指标 | 说明 |
|---|---|
| 每个组分的 MAE（百分点） | helper / sterol / PEG 各报一个，原空间，这是最直观的「差多少」 |
| 三组分整体 MAE（百分点） | 三个组分的平均 |
| 每个组分的 R²（原空间） | 和常数基线的对比口径 |

任务要求「多输出任务要同时报告每个输出的单独指标和整体指标」，上面的表就是按这条来的。

### 2.3 T3（2026-10-19 新增）

**主指标：balanced accuracy（各类召回率的算术平均）。** 不用普通准确率，因为四类分布是 27 / 17 / 9 / 7，多数类占 45%，普通准确率会奖励「永远猜多数类」。

**辅助指标**：macro-F1；每一类的召回率和精确率；混淆矩阵（写进 `metrics.json`，并在 figures 里画出来）。

决策统计量同 T1：模型与基线在同一批 out-of-fold 预测上的配对差值 + cluster bootstrap 95% CI。

## 三、必须打败的基线

这是判断模型有没有用的底线。**如果打不过这两个，就是没有用，如实写出来。**

### B0 常数基线

- T1：永远预测训练折的 `log10(size)` 均值
- T3：永远预测训练折的多数类
- T2：永远预测训练折的**成分中心**（compositional center，即 ILR 空间的均值逆变换回原空间，等价于几何平均后归一化）。不能用算术平均，那不是成分数据的正确中心

### B1 相似性基线（Tanimoto 最近邻）

- 对 payload 分子算 Morgan 指纹（radius=2，2048 位，RDKit `GetMorganFingerprintAsBitVect`）
- 在**训练折内**找 Tanimoto 相似度最高的化合物，直接用它的目标值
- T1：如果该化合物在训练折里有多个配方，取这些配方目标值的中位数
- T2：同上，取成分中心
- T3：取最相似化合物的类别；该化合物有多个配方时取众数，众数并列时取训练折里的多数类
- 相似度完全相同的多个邻居：全部取出后取中位数 / 成分中心 / 众数
- 这个基线专门用来回答「模型有没有比『照抄最像的那个分子的配方』更强」，这是药物化学家实际会做的事

### 两个诊断基线（不是必须打败的底线，但必须报告，因为它们回答「精度差的原因是什么」）

| 基线 | 做法 | 回答什么问题 |
|---|---|---|
| **B2 无分子特征** | 只用制剂特征 + 工艺特征，去掉全部 payload 分子特征 | 如果 B2 和完整模型打平，说明**分子特征没有贡献**，也就是「从分子性质预测」这个任务定义在当前数据上不成立。这是本轮最关键的诊断之一 |
| **B3 只有分子特征** | 只用 payload 分子特征，去掉制剂和工艺特征 | 如果 B3 远差于完整模型，说明粒径主要由工艺和配方决定，分子只是次要因素 |

B2 和 B3 各用 Ridge 和梯度提升树两种模型跑，口径与主模型完全一致。

## 四、数据划分

### 4.1 硬性约束

**同一化合物的不同记录绝对不能同时出现在训练集和测试集。** 分组键是 payload 的标准化结构标识（`payload_smiles` 经 RDKit 规范化后的 InChIKey，避免同一化合物两种 SMILES 写法被当成两个分组；本子集已确认 22 个 SMILES 对应 22 个化合物，没有这种情况，但为跨子集复用仍按 InChIKey 分组）。

### 4.2 四种划分方式，全部报告

| 代号 | 划分方式 | 折数 | 说明 |
|---|---|---|---|
| **S1（主）** | 按化合物分组，5 折 | 5 | 每折测试集约 3 个化合物（15 个化合物的 20%），约 15 个配方。按种子打乱分组顺序 |
| **S2** | 按 Murcko 骨架分组，5 折 | 5 | 任务要求的骨架划分 |
| **S3** | 按论文（`paper_doi`）分组，5 折 | 5 | 只为和前一轮的 R²=−0.069 对比口径，不作为主结果 |
| **S4** | 留一化合物（LOCO） | 15 | 确定性，不依赖种子，最大化训练数据利用；7 个只有 1 个配方的化合物在这里是单点测试折 |

**S1 和 S2 在本子集上几乎等价，这一点必须在报告里写明。** 15 个化合物对应 15 个唯一骨架（MW ≤ 900 口径下一一对应），所以骨架划分和化合物划分是同一件事。任务要求用「随机划分 vs 骨架划分的差距」来诊断能否泛化到新化学结构——**在这个子集上这个诊断测不出化学泛化能力，两者差距只反映划分随机性。不许把「两者差距小」解读成「模型泛化良好」。**

**S3 不是 S1 的替代。** 一个化合物可以出现在多篇论文里（doxorubicin 横跨 16 篇），所以按论文分组并不保证化合物不跨集；反过来按化合物分组也不保证论文不跨集。两者谁更严格不能一概而论。同时满足「化合物不跨集且论文不跨集」的划分在这个数据上会让训练集剩不下东西，**已确认不可行**，因此不做。

### 4.3 不单独留 holdout 测试集

15 个化合物，如果再切出一个 holdout，训练集只剩 12 个化合物，而 holdout 本身只有 3 个化合物——这个 holdout 的任何数字都没有意义。**交叉验证本身就是本轮的评估**，不额外留 holdout。这是样本量决定的，不是图方便。代价是没有一个完全未被任何模型选择过程看到的集合，这一点在模型卡里写明。

### 4.4 测试集规模（这是读结果时最该先看的数字）

| 划分 | 每折测试集化合物数 | 每折测试集配方数（约） |
|---|---|---|
| S1 / S2，T1 | 3 | 15 |
| S4（LOCO），T1 | 1 | 1 到 30 |
| T2（LOCO，8 个化合物） | 1 | 1 到 18 |

T2 的 LOCO 里有一折的测试集是 doxorubicin 的 18 个配方，而剔除它之后训练集只剩 9 个配方（67% 的数据在测试集里）。这一折的数字和其它折不可比，报告时单独标出。

## 五、交叉验证

- **T1 主方案**：S1 的 5 折分组交叉验证，× 5 个种子 = 25 次拟合。报告 5 个种子的均值、标准差、最小值、最大值
- **T1 补充**：S2、S3 同样 5 折 × 5 种子；S4（LOCO）确定性，跑一次
- **T2 主方案**：LOCO（8 折）。8 个化合物做 5 折分组会让每折只有 1 到 2 个化合物且分组极不均衡，LOCO 更合适。LOCO 不依赖种子，但模型内部的随机性（随机森林、梯度提升的子采样）仍跑 5 个种子
- **T3 方案**：20 个化合物，按化合物分组 5 折 × 5 种子（主），另跑 LOCO（20 折）。分层不做——分组约束和分层约束在 20 个分组、4 个类别上无法同时满足，强行分层会破坏分组约束，而分组约束是硬性的。因此报告每折的类别分布，便于判断某一折是否因缺类而不可比
- 样本少，所以采用重复交叉验证并报告多次重复的离散程度，这是任务第 5.5 条的要求

## 六、不确定度

**所有指标都必须带置信区间，不许只报一个数。** 两种不确定度来源分开报，不混在一起：

### 6.1 Cluster bootstrap（抽样不确定度）

- 在合并的 out-of-fold 预测上做
- **按化合物重抽样（cluster bootstrap），不是按行重抽样**。理由：同一化合物的多个配方的误差是相关的，按行 bootstrap 会把置信区间算得过窄，这类错误在小样本化学数据上很常见
- 重抽样次数 2000，取 2.5% 和 97.5% 分位数作为 95% CI
- 对「模型 vs 基线」的配对差值也做同一套 bootstrap（在每次重抽样里同时算两者的指标再取差），得到 `ΔMAE_log` 的 95% CI。**这个区间是否跨过 0，是判断模型有没有用的唯一标准**

### 6.2 跨种子波动

- 5 个种子各自的指标全部列出，报均值、标准差、最小值、最大值
- **不许只报最好的种子。** 结果表里必须能看到 5 个种子的全部数字（放在当次 `metrics.json` 里，README 的表格里至少给均值 ± 标准差和 min–max）

### 6.3 两者的关系

跨种子波动反映的是划分方式的随机性，cluster bootstrap 反映的是样本量带来的抽样不确定度。两个都可能很大，而且是不同的东西。报告里分开写，不许只报其中一个。

## 七、特征定义与泄漏控制

特征的具体计算在第三步（特征工程）实现，但**哪些字段允许用、哪些禁止用，在这里先写死**，防止事后调整。

### 7.1 允许的特征分块

| 分块 | 代号 | 内容 |
|---|---|---|
| payload 分子描述符 | M-desc | RDKit 描述符：MolWt、MolLogP、TPSA、NumHDonors、NumHAcceptors、NumRotatableBonds、RingCount、FractionCSP3、NumAromaticRings、HeavyAtomCount、MolMR、BalabanJ（12 个，在第三步文档里逐个写明物理含义） |
| payload 指纹 | M-fp | Morgan 指纹 radius=2，2048 位；由于样本只有 73 个，主模型用按训练折内方差筛过的子集或降维版本，具体做法在第三步定并写进 config，但筛选只能在训练折内做 |
| 制剂组成 | F-comp | `helper_lipid_pct`、`sterol_lipid_pct`、`peg_lipid_pct`（T1 用；T2 里这三个是目标，不能当特征） |
| 脂质结构 | F-lipid | helper / sterol / PEG 三个角色各自的 RDKit 描述符（多组分时取均值）与指纹（按位 OR），沿用 M3 的做法 |
| 工艺 | P | `prep_method_std`（16 类，one-hot）、`process_temp_c_std`（数值） |

### 7.2 禁止使用的字段（泄漏控制，事先声明）

| 字段 | 风险等级 | 理由 |
|---|---|---|
| `structure_type`（从 `process_notes` 解析） | **高危，绝对禁止** | SUV / LUV / MLV 是按囊泡尺寸定义的分类标签，本身就是目标分箱后的结果（实测 SUV 最大 120 nm、LUV 最小 101.1 nm，严格吻合定义边界）。用它等于告诉模型答案 |
| `process_notes` 原始文本 | **高危，绝对禁止** | 包含 `structure_type`，整体做文本特征等于间接引入 |
| `release_curve_file` | 高危 | 纯文件名，等价于记录 ID |
| `source_row_id`、`formulation_id` | 高危 | ID 列 |
| `paper_doi` | 高危 | 论文身份，等价于「同实验室同尺寸档」的查表 |
| `payload_type` 名字的 one-hot | 高危 | 等于让模型背化合物名字对应的答案（M3 已刻意没做，沿用） |
| `is_probe` | 中危 | 只作误差分析的分组标记，不作特征 |
| `measurement_instrument_std` | 中危 | 仪器型号是论文身份的代理变量。**默认排除**，另跑一次「加入」的敏感性对比，结果一并报告 |
| `pdi`、`zeta_potential_mv`、`encapsulation_efficiency_pct`、`formation_ok` | 中危 | 其它目标变量 |
| `source_dataset` | — | 本子集内恒为 PMC_IVR，无信息量；跨子集时它和子集标签完全共线，禁止使用 |
| `ratio_order_was_ambiguous`、`composition_pct_was_renormalized`、`*_was_harmonized`、`*_was_unit_corrected` | 中危 | 数据清洗的审计标记，与数据来源批次相关，是来源的代理变量 |

**泄漏检查要逐个字段确认并把结果写进第三步的文档**（任务第 6 节要求）。检查方法不只是「看字段名」，还要对每个候选特征算它与目标的互信息，以及做一次「只用这一个特征」的单特征模型，异常高的单特征性能要回头查原因。

### 7.3 缺失值处理（写明，不许默默填 0）

| 模型 | 处理方式 |
|---|---|
| 梯度提升树（HistGradientBoosting / XGBoost） | 原生支持缺失值，不做填充 |
| Ridge、随机森林 | 训练折内算中位数填充（`SimpleImputer(strategy="median")`，**只在训练折上 fit**），同时为每个有缺失的列加一个二值缺失指示列 |
| 类别特征（`prep_method_std`） | 缺失作为单独一类 `"missing"`，不丢样本 |

**禁止**：用全体数据（含测试折）算填充值；把缺失静默填 0（0 在占比类特征里意味着「确定不含该组分」，和「没有数据」是两件事，M2 文档里记录过这个 bug 曾经真实发生过）。

## 十、成功标准（事先写死）

本轮的判定只看 T1 的主指标 `MAE_log`，以及它与基线的配对差值的 95% CI。

### 10.1 判定规则

| 结论 | 条件 |
|---|---|
| **成功** | 最好的模型在 **S1 和 S2 两种划分下都**同时打败 B0 和 B1：配对 `ΔMAE_log` 的 95% cluster bootstrap CI 不跨过 0，且 5 个种子的差值符号一致 |
| **部分成功** | 在 S1 下打败两个基线，但在 S2（骨架划分）下没有。结论写成：**模型只能在已知化学空间内插值，泛化不到新结构**。考虑到本子集 S1≈S2，这种情况更可能说明结果不稳定而不是真的泛化差，要在报告里说清 |
| **不成功** | 没有打败 B0 或 B1，或者 CI 跨过 0。结论写成：**以现有小分子数据建不出比「报均值」或「照抄最相似分子」更好的模型** |

### 10.2 无论哪种结论都必须交付的东西

成功标准不是本轮唯一的产出。下面这些**无论结果好坏都要给**：

1. **学习曲线**：按训练集**化合物数**的 20% / 40% / 60% / 80% / 100% 各跑一遍（不是按行数，因为「补数据」在实际中意味着补新化合物，不是把同一个化合物多测几次）。5 个种子。这条曲线用来回答「继续加数据有没有用」，是本轮最重要的产出
2. **从学习曲线外推出一个量化估计**：大约需要多少个新化合物，才可能让 `MAE_log` 的 CI 脱离基线。外推必须标注这是外推、不确定度很大
3. **B2 / B3 诊断结果**：分子特征到底有没有贡献。这直接回答任务第 2.3 条的决策问题（是数据量不够、数据质量问题、特征不对，还是任务定义有问题）
4. **误差分析**：哪些化合物预测得最差，有没有共同点（结构类型、数据来源、取值区间、是否为探针分子）
5. **模型卡**：模型做什么、用了什么数据、性能多少、什么情况下不可靠、不应该用来做什么

### 10.3 预先声明

**如果结论是「不成功」，就按不成功写，不做任何挽救性的调整。** 具体地说，以下做法本轮事先禁止（任务第 11 节）：

- 不许为了指标好看删除难预测的样本（比如把 bupivacaine 或 MLV 相关样本再剔一轮）
- 不许事后改异常值处理方式或过滤阈值（`≤1000 nm` 已写死）
- 不许事后改测试集或划分方式
- 不许在测试集上调参，不许用测试结果反过来改特征或模型选择
- 不许只报最好的种子或最好的一次划分
- 不许把没有数据支撑的话写进结论（「有潜力」「表现良好」这类表述禁止）

「以现有小分子数据建不出有用的模型」是一个有价值的结论，它告诉我们下一步该补什么数据。本轮事先接受这个结论的可能性。

## 十一、为大分子对比做的约定（本轮不跑，但现在定死）

之后在大分子子集上跑时，**下面这些必须原样使用，不许两边用不同标准**：

1. 同一套指标（主指标 `MAE_log`，辅助指标同第二节）
2. 同一套划分方式（S1–S4，分组键同为化合物的 InChIKey）
3. 同一组种子（0–4）
4. 同一套基线（B0 常数、B1 Tanimoto 最近邻、B2/B3 诊断）
5. 同一条去重规则（第 1.1 节的去重键，目标取中位数）
6. 同一套泄漏排除清单（第 7.2 节）
7. 同一套超参数网格和嵌套调参方式（第八节）

### 11.1 两个子集样本量不同，怎么比才公平

这是跨子集对比最容易出错的地方。小分子子集 15 个化合物，大分子子集的 payload 只有 6 类（mRNA / siRNA / DNA / ASO / protein / mRNA+siRNA），**大分子那边根本没有「化合物」这个概念上的多样性**——1033 条记录对应 6 个 payload 类别。所以：

1. **不能直接比两边的 `MAE_log` 绝对值。** 目标变量的分布范围不同（小分子 30–820 nm，大分子另一个范围），MAE 的尺度不可比
2. **要比的是「模型相对于各自基线的提升幅度」**，即 `ΔMAE_log vs B0` 和 `ΔMAE_log vs B1`，这是无量纲的相对量
3. **要在匹配的样本量上比。** 把大的那个子集按分组数下采样到与小的一致（按化合物/payload 类别数，不是按行数），跑同一套流程，报告匹配后的结果；同时报告全量结果
4. **最该比的是学习曲线的形状**，不是单点指标。两条曲线在同样的横轴（分组数）上画出来，斜率的差别才是「哪边更有希望」的证据
5. **必须声明一个无法消除的混杂**：小分子子集 = PMC_IVR = 经典脂质体 = 无可离子化脂质；大分子子集 = LNP_Atlas = 现代 LNP = 有可离子化脂质。子集标签、数据来源、脂质体类型三者完全共线（盘点文档 1.3 节）。**所以两边的差异不能归因为「小分子 vs 大分子」，只能表述为「这两个数据集之间的差异」。** 这一条写进两轮的 README，不许省略

### 11.2 分组键在大分子子集上会退化，事先定好怎么处理

这是「原封不动套用」最先会撞上的问题，现在定下来，避免到时候临场改标准。

小分子子集的化学多样性在 payload 上（15 个化合物）。大分子子集的 payload 只有 6 个类别（mRNA / siRNA / DNA / ASO / protein / mRNA+siRNA），**按 payload 分组只剩 6 个分组**，而且这 6 类不是「结构」而是「类别」，算不出 Tanimoto 相似度，B1 基线在那边无法按原样实现。同时大分子子集真正变化的分子是**可离子化脂质**（940 条有结构，M6 的骨架聚类结果显示有几十个不同骨架）。

所以在大分子子集上要跑三套分组，全部报告：

| 分组键 | 分组数（预估） | 用途 |
|---|---|---|
| `payload_type`（6 类） | 6 | 与小分子的 S1 概念对应（按被递送物分组），但分组数太少，B1 无法实现，只报 B0 |
| 可离子化脂质的 InChIKey | 待统计 | 大分子侧真正的化学多样性所在；B1 的 Tanimoto 改为在可离子化脂质上算 |
| `paper_doi` | 60 左右 | **跨子集对比的主口径** |

**跨子集对比的主口径用 S3（按论文分组），因为它是唯一在两个子集上定义完全相同、分组数都够的划分方式。** 小分子侧 26 篇论文，大分子侧 60 篇左右。本轮在小分子上已经按协议跑了 S3，所以到时候两边有同口径的数字可比。

另外两套分组的结果作为补充，并在报告里写明它们的分组键不同、不能直接对比绝对值，只能比「相对基线的提升幅度」和学习曲线斜率。

`scripts/compare_subsets.py` 按 11.1 的五条和 11.2 的分组规则写框架（本轮只写框架不跑）。
