## 二、跑之前写定的一个特征决定

**脂质指纹不进模型。** helper 和 sterol 各 512 位 Morgan 指纹，共 1024 列，39% 的行缺失（天然混合物如 HSPC、Soy PC、EPC、asolectin 在原始文献里就没有单一结构式）。58 行的训练折无法可靠筛选 1024 个高缺失的二值位。脂质结构仍由 24 个描述符和 7 个派生标记表示。

这个决定写在 `scripts/run_modeling.py` 的 `feature_sets()` 注释里和建模 README 第十一节，是在跑任何模型之前定的，不是看到结果之后调的。

payload 指纹（2048 位，零缺失）保留，位的筛选在折内做，k ∈ {0, 32, 128} 作为超参由内层交叉验证决定——k=0 表示完全不用指纹，等于让数据自己回答「指纹有没有用」。

## 三、踩到的坑（都影响结果可信度，逐条记录）

### 3.1 三个会让整轮结果丢掉的代码问题（跑之前发现）

跑小规模试跑时暴露了三个问题，全部在正式跑之前修掉：

1. **配对比较的样本一致性断言对字符串标签会抛异常**。`np.asarray(y, float)` 在 T3 的类别标签上直接报错。这个 bug 会在 T1 和学习曲线都跑完之后才触发，而 `metrics.json` 原来只在最后写一次，等于把前面两小时的结果一起丢掉。改用 `np.array_equal`，并把 `metrics.json` 改成每跑完一段就落盘。
2. **指纹的折内筛选在多输出（T2 的 2 维 ILR 坐标）下报 `y should be a 1d array`**。改成每个输出各算一次 f 统计量、取每个特征的最大分。
3. **学习曲线最小点无法拟合**。20% 那个点训练子集只有 2 个化合物，内层交叉验证的训练折退化成一两行，很多列变成常量，`HistGradientBoosting` 分箱时对只有一个 distinct 值的列会抛 `window shape cannot be larger than input array shape`。

### 3.2 第 3 个问题的处理方式值得单独记

先试了给所有模型都加「折内剔除常量列」，然后**逐个核对它会不会改变已经跑完的结果**：

| 模型 | 加之前 | 加之后 | 一致 |
|---|---|---|---|
| 梯度提升树 | 0.1663 | 0.1663 | 是 |
| Ridge | 0.2859 | 0.2808 | **否** |
| 随机森林 | 0.1921 | 0.1950 | **否** |

Ridge 和随机森林会变，因为丢列会改变 `SimpleImputer(add_indicator=True)` 生成的缺失指示列数量，以及随机森林的特征子采样。而这两个模型本来不会因常量列报错。

所以改成**只给梯度提升树加**，重新核对三个模型全部与已跑完的结果完全一致，才继续。这样已经跑完的 S1–S4 结果不受影响，也不需要为了一个工程问题重跑两小时。

另外加了显式降级：分组数 < 3 或样本 < 6 时跳过网格搜索用默认超参；仍然拟合失败就降级成常数预测并计数。**降级计数写进 `metrics.json`，主结果里这个数是 0**（每折训练集都有 11 个以上化合物）。

### 3.3 容器重启和后台时限

建模过程中容器重启 2 次、后台任务时限触发 3 次。最惨的一次：T1 的 180 次拟合**全部跑完了**，但进程在写 `metrics.json` 之前被 2 小时上限掐掉，结果只能从日志里抢救逐次的 MAE 和 R²。

处理办法：给 `run_modeling.py` 加 `--schemes` 参数支持分段跑，并让 `metrics.json` 在已存在时读回来合并、只更新本次跑的部分。最终 `metrics.json` 是分五段合并写出的，`runs` 字段记录了每一段跑了什么。

**分段不影响结果**：每一段用同一份配置、同一组种子。而且有一个现成的一致性自检——学习曲线 100% 那个点是独立重算的，MAE 0.1663 与 S1 seed0 的主结果完全一致。

### 3.4 T3 的 S3 划分没跑

协议第五节对 T3 只规定 S1 为主、留一化合物为辅，S3 不是 T3 的要求。实际跑了 S1、S2、S4。跑 S3 的尝试撞上后台时限被中止，中止前只完成了 B0 和 B1，`metrics.json` 里没有留下残缺条目（已核对）。这条写进了建模 README 的执行偏差一节。

## 四、结果（只记关键的，完整版在建模 README）

### 4.1 主判定

**没有任何模型在任何一种划分下打败 B0 常数基线。** 梯度提升树在 S1 下点估计好 24%（0.192 vs 0.253），但配对 ΔMAE 的 95% cluster bootstrap 区间是 [−0.052, +0.267]，5 个种子里 0 个区间排除 0，连差值的符号在种子之间都不一致。

按协议第十节事先写死的标准：**不成功**。

### 4.2 三条诊断指向同一个答案

1. **B2 去掉全部分子特征，性能基本不变**（S1：0.192 → 0.198；S4 甚至更好：0.151 → 0.138）
2. **B3 只用分子特征，打不过常数基线**（0.257 vs 0.253）
3. **S3 按论文分组时，优势从 0.061 掉到 0.003**

第 1、2 条说明分子特征没有贡献；第 3 条说明剩下的那点优势有相当一部分是论文身份的查表。两者都是协议事先规定要跑的，不是事后找的解释。

### 4.3 一个直接证据

atenolol 和 propranolol 来自同一篇论文，同样的脂质组成，只因制备方法不同（超声 vs 搅拌）粒径就从 30 nm 变到 800 nm，相差 25 倍；而两个 LogP 相差 2 个数量级的药物在相同工艺下给出完全相同的粒径。

这解释了为什么制备方法单独一个特征就能带来 29.1% 的改善（第三步的单特征诊断），也解释了为什么分子描述符学不出东西。

### 4.4 学习曲线是本轮最有价值的产出

| 训练集化合物数 | 2 | 5 | 7 | 10 | 12 |
|---|---|---|---|---|---|
| 梯度提升树 MAE | 0.309 | 0.302 | 0.259 | 0.225 | **0.192** |
| 常数基线 MAE | 0.269 | 0.248 | 0.245 | 0.250 | 0.253 |

模型要到约 8 个训练化合物才开始超过常数基线，而曲线在 12 个化合物处**仍在陡降、完全没有走平**。外推估计需要 40–100 个唯一化合物才可能得到统计上站得住的结论（现在 15 个）。这个外推在 README 里明确标注了是外推、不确定度很大。

### 4.5 两个探针任务

- **T2**：梯度提升树的每一项指标都与常数基线**完全相同**（Aitchison 0.446、整体 MAE 5.78 个百分点），小数点后三位都不差。模型学到的最优策略就是「永远输出训练集的平均配方」。零信号。
- **T3**：最好的模型 balanced accuracy 0.273，而四分类的随机水平就是 0.25。混淆矩阵显示模型把样本都丢进两个最常见的类，`helper_peg` 的 35 个样本一个都没答对。

## 六、第六步：为大分子对比做的准备

- **子集可配置**：`lnp/subset.py` 把三个 payload 集合写成模块级常量，`select()` 按 `subset.name` 分派。换大分子只改 config 里一行。
- **评估流程封装成可复用模块**：`lnp/evaluation.py` 不含任何小分子特有逻辑，任务类型、划分、种子、基线都是参数。
- **`scripts/compare_subsets.py` 框架已就位**（本轮不跑）：缺大分子侧产出时会打印还需要跑什么；有了之后会先逐项核对两边的协议设定是否一致，不一致直接拒绝对比。
- **对比规则写进脚本文档字符串**：不比 MAE 绝对值（两边目标分布范围不同），比相对各自基线的 skill score；按分组数下采样到匹配样本量；最该比的是学习曲线斜率；主口径用 S3 按论文分组（唯一两边定义相同、分组数都够的划分，本轮小分子已跑）。
- **强制声明的混杂**：子集标签、数据来源、脂质体类型三者完全共线，两边差异只能表述为「这两个数据集之间的差异」。这句话同时写进了建模 README 第十节和 `compare_subsets.py`。
