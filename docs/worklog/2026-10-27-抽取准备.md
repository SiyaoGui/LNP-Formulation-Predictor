## 一、做了什么

| 产出 | 文件 | 说明 |

## 二、授权核实的事实来源

全部取自 Crossref API 的 `license` 字段，`content-version = vor`（版本记录）那一条。容器的网络策略只放通 `api.crossref.org`，zenodo.org 与各出版商域名被拦，**本轮按用户要求不再尝试绕过**。

四个可用数据集全部确认 CC BY 4.0：

| 数据集 | DOI | 授权 URL |
|---|---|---|
| Khawar 2022 | `10.1038/s41598-022-19452-6` | `https://creativecommons.org/licenses/by/4.0` |
| Yanes 2025 | `10.1016/j.ijpx.2025.100393` | `http://creativecommons.org/licenses/by/4.0/` |
| Jaki 2026 | `10.1016/j.ijpx.2026.100627` | `http://creativecommons.org/licenses/by/4.0/` |
| Xu 2022 | `10.3390/molecules27227967` | `https://creativecommons.org/licenses/by/4.0/` |

完整署名串（CC BY 要求）已逐条写入 `docs/data-licensing.md` 第二节，抽取时写进每条记录的 `source_attribution`。

## 三、基线数字已核定

`python3 scripts/report_compound_gain.py` 在当前仓库状态下的输出：

| 指标 | 值 |
|---|---|
| 小分子记录数（无 MW 上限） | 272 |
| 小分子记录数（MW ≤ 900 Da） | 230 |
| **唯一化合物（InChIKey）** | **22** |
| 唯一化合物（MW ≤ 900） | 20 |
| 唯一化合物（payload_smiles） | 22 |
| 唯一 Murcko 骨架（非空） | 20 |
| 骨架为空的记录 | 1 |
| 来源论文（唯一 DOI） | 34 |

两处口径和 `docs/data-inventory.md` 对账：

1. **化合物数 22 两种口径一致。** InChIKey 口径会合并同一化合物的不同 SMILES 写法，这里没有发生合并，说明现有数据没有重复写法
2. **骨架数本脚本报 20，`data-inventory.md` 报 21。** 差在空骨架：Hydroxy-alpha-sanshool 是链状分子，Murcko 骨架为空。本脚本只数非空骨架并单列空骨架记录数，20 + 1 = 21，两边能对上。口径说明已打印在脚本输出里

## 四、环境变动

**本容器没有预装 RDKit**，`scripts/report_compound_gain.py` 和 `scripts/data_inventory.py` 都依赖它。本轮用 `pip install rdkit` 装好（pypi.org 在网络策略的放通名单里）。

`docs/data-inventory.md` 记录上一轮用的是 RDKit 2026.09.1，本轮装的是 pip 当前版本。骨架与 InChIKey 的计算结果和上一轮能对上（见第三节对账），所以版本差异暂未造成影响。若后续发现差异，以本轮脚本输出为准并记录。

## 五、等用户提交原始文件后的执行顺序

按用户指定的优先级：

1. **Khawar 2022** 先做。对应这一轮要检验的核心假设（辛醇/水 logP 是否对磷脂双层有系统性偏差）
2. Yanes 2025
3. Jaki 2026
4. Xu 2022 抽成独立探针集

每个数据集抽完的动作固定为四步：

1. `python3 scripts/record_raw_checksums.py` 登记校验值
2. 跑该数据集的抽取脚本（抽取脚本在拿到文件后写，不预先猜列名）
3. `python3 scripts/report_compound_gain.py` 出增量报告
4. 在本日志追加一节，报告用户要求的五个数字

**三个都抽完后停下，等用户确认再进特征对比实验。**
