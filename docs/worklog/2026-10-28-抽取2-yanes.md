## 一、最重要的发现：这不是新数据源

**Yanes 2025 就是仓库里 PMC_IVR 的来源。** 三项验证全部通过：

| 验证 | 结果 |
|---|---|
| 化合物比对（InChIKey） | 交集 **22**，仅 Yanes 有 **0**，仅仓库有 **0** |
| 记录连接（仓库 `release_curve_file` 的数字 ↔ Yanes `IVR_ID`） | **271 行全部连上** |
| 化合物名一致性 | **271 / 271** |
| 粒径数值一致性 | 两边都有值的 216 条，**216 / 216 完全相同**（差 < 0.51 nm） |

22 个化合物名逐字相同：5-Fluorouracil carbonate、BAY 87-2243、Hydroxy-alpha-sanshool、amoxicillin、amphotericin B、atenolol、budesonide、bupivacaine、calcein、carboxyfluorescein、doxorubicin、fraxetin、gemcitabine、hydrocortisone、methotrexate、paclitaxel、propranolol、rhodamine b、sulforhodamine B、temoporfin、tetrodotoxin、vincristine sulfate。

规模：Yanes 271 行 / 140 个配方，仓库 PMC_IVR 272 行 / 141 个配方。差一行。

**所以抽取形态从「配方表」改成了「增补表」**，产物是 `yanes2025_enrichment.csv` 而不是 `formulations_yanes2025.csv`。按新配方表抽会造成重复记录。

## 三、实际价值：给已有的 272 条记录补字段

虽然 0 个新化合物，但补上了仓库 schema 里没有的东西：

| 新字段 | 非空 | 说明 |
|---|---|---|
| **`drug_loading`** | **249 / 271** | **填的正是 `docs/literature-protocol.md` 3.4 节标出的那个空缺**：「现有 schema 完全没有这一列，而它是包封率的一级决定因素」 |
| `media_volume_mL` | 209 / 271 | 仓库无此列 |
| `media_temp_oC` | 259 / 271 | 仓库只有从 `process_notes` 解析的部分信息 |
| `media_components` | 271 / 271 | 34 种组分（PBS、HEPES、sucrose、NaN3、NaCl、FCS、HP-CD、γ-CD 等）。仓库原来只有 `media_pH` |
| 质量评级 6 列 | 大部分非空 | 逐条的 Units、Plot Resolution（Poor/Medium）、测量时间点是否足够、曲线形状是否像释放曲线、重复数是否足够 |

另外 Yanes 明确区分 `formulation_ID`（140 个）与 `IVR_ID`（271 个），每个配方的 IVR 次数分布是 `{1次:101, 2次:15, 3次:10, 4次:7, 6次:2, 12次:2, 11次:1, 15次:1, 20次:1}`。

**这个区分权威地解决了 `docs/data-inventory.md` 3.3 节的那个问题**：该节只能推断「216 条有粒径的记录对应 76 个唯一（化合物+配方+论文）组合」，现在有了作者自己的配方编号，不用再推断。这正是 `docs/literature-protocol.md` 3.6 节定义的 `study_block_id`。

## 四、质量评级这一项值得单独说

`quality_reporting.csv` 给了逐条的数据质量判断，这是仓库完全没有的。意味着现有 272 条记录可以按质量筛选或加权，而不是一视同仁。

例如 `Plot Resolution` 有 Poor / Medium 之分，`是否有足够重复并给出均值` 有 Yes / No 之分。前一轮建模把所有记录等权处理，这批评级提供了一个此前不存在的筛选维度。

## 五、释放曲线不在这个包里

`docs/data-inventory.md` 出入三记录：272 条记录的 `release_curve_file` 指向的 csv 在仓库里一个都不存在。

4.4 MB 的 GitHub 快照里**也没有**。它只有后端数据库（271 行）、介质组分（563 行）、质量评级（222 行）、分析代码和图。数字化的释放曲线应该在 269 MB 的诺丁汉机构库存档（`standardisation_nm_IVR.zip`，DOI `10.17639/nott.7542`）里。

该文件超过 GitHub 单文件 100 MB 上限，已在 `.gitignore` 里排除。释放动力学本轮不作为目标（`data-inventory.md` 4.1 节 F 项），所以暂不追。若将来要做释放预测，这是唯一的来源。
