## 一、开头就撞上一件要改协议的事

动手写特征代码时第一件事是搞清三个组分占比列的缺失结构。查出来的结果和盘点阶段的理解不一样：

- `*_lipid_name` 和 `*_lipid_pct` 两列几乎完全同时存在、同时缺失（helper 2 行、sterol 2 行例外）
- 把占比列的 NaN 当 0 填回去之后，**270 行里每一行的三组分加总都精确等于 100.000**（按 presence pattern 分组看：100 模式 56 行、101 模式 36 行、110 模式 88 行、111 模式 90 行，四组的 min=median=max=100.0）
- 只有 `IVR_formulation_41` 和 `49` 两行是三列全空的真缺失（M2 文档记录过这两行曾被 pandas 的全 NaN 求和静默算成 0.0，后来用 `min_count=1` 修掉）

所以这些 NaN 不是缺失值，是「该配方不含这类组分」。盘点阶段按「NaN = 缺失」处理，把「用了哪几类脂质」这个在 230 行上都观测到的信息当成了只有 88 行可用。

这件事有两个后果，分别处理了：

1. **特征侧**：占比填 0 + `has_*` 标记，而不是留 NaN 让折内中位数填充。填中位数会把「不含 PEG」变成「含约 5% 的 PEG」，是实质性的错误。
2. **任务侧**：新增 T3（脂质类别组合四分类，60 个分析单元 / 20 个化合物 / 29 篇论文）。按协议「确需修改要单独提交并写明原因」，T3 作为**独立一次提交**先推上去了（提交信息里写明原因、写明当时没有任何模型结果、并指出可从 git 历史核实这次提交在任何 `modeling/` 目录出现之前）。T1 和 T2 的定义、指标、划分、基线、成功标准一个字没动。

这是理解错误的修正，不是结果驱动的调整——修正时还没跑过任何模型。

## 二、实现上的几个决定

### 2.1 不用脂质名字的 one-hot

协议 7.2 节已禁止，这里确认了禁止的理由在数据上成立：30 个 helper 名字里很多只出现一两次，73 个分析单元配 30 个类别，等于论文标识。

替代方案是结构描述符 + 三个化学含义明确的派生标记：`n_*_components`（单一脂质 vs 混合脂质）、`*_is_natural_mixture`（天然混合物，这类没有单一结构式）、`peg_mw_da`（PEG 链长 2000/5000/10000，从名字解析）。

### 2.2 PEG 不造近似结构

M3 曾给 PEG 脂质造「平均链长近似结构」再算描述符。本轮不这么做：本子集只有 4 个 PEG 名字，差别主要就是链长，编一个假 SMILES 再从它算 12 个描述符，得到的是 12 个由同一假设推导出的相关列，信息量不比一个 `peg_mw_da` 多，还让人误以为有结构数据。

### 2.3 指纹存全量，筛选留到折内

2048 位配 73 个样本是严重过参数化的。协议第七节写明筛选只能在训练折内做，所以特征矩阵存全量 2048 位，筛选推到第四步。代价是建模代码要自己管这件事，好处是不会出现「用全体数据筛特征」这种泄漏。

### 2.4 禁止字段断言做成硬失败

`build_features.py` 对协议 7.2 节的 19 个禁止子串逐列匹配，命中就 `raise SystemExit` 直接退出。不是打印警告——警告会被忽略。

### 2.5 缺失值：0 只用在确实是 0 的地方

四种情况分开处理（细节写进 `docs/feature-engineering.md` 第三节）。特别是脂质没有结构式时，描述符和指纹整行留 NaN 而不是 0：指纹全 0 意味着「所有子结构都不存在」，和「没有结构数据」是两件事。

### 2.6 子集可配置的落地方式

`lnp/subset.py` 里把三个 payload 集合写成模块级常量（`LARGE_PAYLOADS` / `NON_DRUG_PAYLOADS` / `PROBE_PAYLOADS`），`select()` 按 `subset.name` 分派。换大分子子集只改 config 里一行。`payload_group_key()` 用 InChIKey 做分组键，并在代码注释里写明大分子侧会退化成 `payload_type`（协议 11.2 节已定好怎么处理）。

## 四、泄漏检查结果

五项检查全部跑了，完整结果在 `docs/leakage_check.json`，逐特征明细在 `docs/leakage_check_detail_t1.csv` / `_t3.csv`。

**通过的四项**：

1. 禁止字段断言：T1 的 3133 列、T3 的 2060 列，0 命中
2. |Spearman ρ| 最大 0.505（T1）/ 0.583（T3），没有特征是目标的单调变形
3. 对被排除的 `structure_type` 的代理增益最大 0.154（T1）/ 0.117（T3）——排除掉这个高危字段之后，没有留下能把它还原回来的特征。这是最关键的一项
4. 单特征模型：61 个非指纹特征里只有 5 个能单独打败常数基线

**有问题的一项，必须写出来**：

被 `paper_doi` 解释的方差 η² 中位数 **0.825**，四分之一的特征超过 0.914，**`prep_Thin lipid film hydration` 和 `prep_microfluidics` 两个特征达到 1.000**——这两种制备方法各自只出现在一篇论文里，数值上等价于论文指示变量。

性质要说准：这不是协议 7.2 节意义上的泄漏（没有特征包含目标值），但它是一个真实的混杂通道——按化合物分组时同一篇论文可以跨训练测试折（一篇论文里可以有多个化合物），此时等价于论文标识的特征就能让模型查到「这篇论文的典型粒径」。根源是数据结构本身：26 篇论文 73 个配方，每篇论文往往只用一套工艺和一种脂质体系。

**处理方式：没有新增任何特征处理或过滤条件，用协议里已经定好的两个手段。** 协议第三节已规定要跑 B3（只用分子特征，不含任何工艺特征，因此不含这两列）；第四节已规定要跑 S3（按论文分组，同一论文不可能跨折）。**S1 与 S3 的差距就是这个混杂程度的直接度量**，第五步按这个口径解读。协议冻结后不为结果好看调整做法。

## 五、一个要记下来的方法论发现

T1 互信息最高的非指纹特征是 `payload_hba`（0.651）、`payload_heavy_atoms`（0.632）、`payload_mol_wt`（0.603），看起来分子描述符很有信息量。

但这几个特征在单特征分组交叉验证里**全部打不过常数基线**：`payload_hba` 改善 −0.030、`payload_heavy_atoms` −0.012、`payload_ring_count` −0.097、`payload_mol_mr` −0.124（负数表示比直接报均值更差）。

原因：73 个样本上互信息估计方差极大，而且这些描述符在同一化合物内部是常量，互信息捕捉到的其实是「化合物身份」，不是可泛化的关系。

**结论：在这个样本量下互信息不能用来筛特征，单特征分组交叉验证才是有效诊断。** 这条专门写进了 `docs/feature-engineering.md`，防止之后有人拿互信息排序去做特征选择。

同时，单特征里最强的是**制备方法**（改善 +29.1%，MAE 0.176 vs 常数基线 0.248），不是任何分子性质。这在建模前就提示 B2（去掉全部分子特征）会很强、分子特征贡献很可能很小。这是预期不是结论，结论要等第四步按协议跑完。
